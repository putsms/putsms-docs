该项目包含 Cloudflare Worker、D1 迁移、Durable Object、Queue 绑定和后端环境。

## 本地开发

```sh
pnpm install
pnpm db:migrate:local
pnpm dev
```

也可使用 `pnpm dev:migrated` 自动迁移后启动。Worker 默认运行于 `http://localhost:8787`；Dashboard 使用 `VITE_API_BASE_URL=http://localhost:8787 pnpm dev` 连接。

## 环境

- `DB`：D1 数据库。
- `USER_REALTIME`：SSE 实时事件 Durable Object。
- `APNS_QUEUE`：APNs Queue。
- `SMS_ENCRYPTION_KEY`、`SESSION_SECRET`：必需 Secrets。
- `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`GOOGLE_REDIRECT_URI`：Google OAuth。
- `FRONTEND_BASE_URL`、`ALLOWED_ORIGINS`：前端跳转与 CORS。
- `APNS_TOPIC`、`APNS_ENV`、`APNS_KEY_ID`、`APNS_TEAM_ID`、`APNS_PRIVATE_KEY`：APNs。

敏感值使用 `wrangler secret put` 设置，不要写入 `wrangler.jsonc`。

## 常用命令

- `pnpm dev`：在 `8787` 端口运行 Worker。
- `pnpm typecheck`：生成 Wrangler 类型并运行 TypeScript 检查。
- `pnpm test`：运行后端测试。
- `pnpm db:migrate:local` / `pnpm db:migrate:remote`：应用本地/远端迁移。
- `pnpm deploy`：迁移并部署；`pnpm deploy:worker-only` 只部署 Worker。

创建设备不会返回凭据。所有者先选择一种凭据展示方式：

```http
POST /api/v1/devices/:deviceId/connection-method
Content-Type: application/json

{ "connectionMethod": "api_key" }
```

允许值为 `api_key`、`put_url` 和 `sms_registration`。

选择 `api_key` 或 `put_url` 后，通过 `POST /api/v1/devices/:deviceId/credentials` 生成长期 Device Key；响应仅显示一次 `deviceKey`、`putUrl` 和 `revealedAt`。同一个 Key 既可通过 `Authorization: Bearer <deviceKey>` 调用 `POST /api/v1/messages`，也可用于 `POST /put/:deviceKey`。两者均接受 JSON 或表单格式的 `sender` 与 `content`。生成 Key 后设备为 `ready`，首次成功鉴权请求后才变为 `connected`；Key 不会自动过期。

Dashboard 为 iOS 和 Android 设备都提供 PutSMS App 与 Webhook 连接方式；Platform 只决定默认推荐项，不限制可用连接方式。Webhook 使用生成的 `putUrl`，接受以下 canonical JSON：

```json
{
  "sender": "+15551234567",
  "receiver": "+15557654321",
  "content": "Verification code: 123456",
  "receivedAt": "2026-09-22T08:30:00.000Z",
  "simSlot": "1",
  "clientVersion": "your-client/1.0.0"
}
```

SmsForwarder `v3.3.1+` 使用同一个 Webhook URL，并可复制以下预设：

```json
{
  "sender": "{{FROM}}",
  "content": "{{SMS}}",
  "receivedAt": "{{RECEIVE_TIME}}",
  "simSlot": "{{CARD_SLOT}}",
  "clientVersion": "{{APP_VERSION}}"
}
```

接口只要求 `sender` 和 `content`。SmsForwarder 没有接收号码模板变量，因此预设省略可选的 `receiver`；用户可填写固定的 SIM 手机号。不得用 `CARD_SLOT` 或 `CARD_SUBID` 代替接收号码。Put URL 内嵌的 Device Key 已是 bearer 凭据，不需要额外的 SmsForwarder Secret、`timestamp` 或 `sign`。

## SMS 注册

选择 `sms_registration` 后，任意平台都可以通过以下接口创建十分钟有效、仅可使用一次的注册码：

```http
POST /api/v1/devices/:deviceId/enrollment-code
```

设备无需已有 Session 或 Device Key 即可兑换：

```http
POST /api/v1/device-enrollments/redeem
Content-Type: application/json

{
  "code": "XXXX-XXXX",
  "platform": "embedded",
  "clientVersion": "001.999.006",
  "hardwareFingerprint": "sha256:<64 位十六进制字符>"
}
```

兑换成功后返回 API 地址、设备 ID、生成的 Device Token 和显示 ID，并立即将设备标记为已连接。生成与兑换都有限流；已使用注册码返回 `409`，无效或过期返回 `400`。是否能够自动兑换取决于对应 App 或固件的实现。

所有连接方式都使用 `POST /api/v1/devices/:deviceId/disconnect` 断开。接口撤销当前 Key、作废未使用注册码，并清除配对和同步时间，但保留设备、短信、备注和加密密钥绑定。`/unenroll` 仅作为兼容别名保留，不再推荐使用。已连接设备必须先 Disconnect，才能切换连接方式。

设备响应包含 `connectionMethod` 和 `connectionState`。没有有效凭据时为 `not_connected`；存在未使用 Key 或有效注册码时为 `ready`；Key 成功使用或 SMS 注册码兑换后为 `connected`。
