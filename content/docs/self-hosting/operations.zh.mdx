## 升级顺序

1. 阅读迁移和客户端兼容说明。
2. 备份或导出 D1 数据库，并单独保存客户端私钥备份。
3. 运行 API 类型检查和测试。
4. 先应用 D1 迁移，再部署依赖新结构的 Worker。
5. 部署 Worker，随后部署 Dashboard 和客户端。
6. 完成下面的验证清单。

## 可观测性

启用 Worker Observability 和 Source Maps。关注请求错误与延迟、D1 失败与读取量、Durable Object/SSE 断线、Queue 重试和死信、APNs 拒绝原因及限流响应。不要记录短信正文、Device Key、Put URL、Session Cookie 或私钥。

## 验证清单

- 注册和登录正常，OAuth 回调返回正确前端。
- 新 Device Key 可以上传，轮换或撤销后的旧 Key 无法上传。
- Dashboard 列表、搜索、联系人、已读状态和删除正常。
- iOS 离线使用后，增量推拉最终收敛。
- SSE 更新正常，断线后轮询可以接管。
- APNs Queue 能排空，测试设备收到通知。
- E2EE 密文只能由持有匹配私钥的客户端解密。
- CORS 拒绝未列出的 Origin，生产客户端全部使用 HTTPS。

需要回滚时，不要假设 D1 迁移可逆。优先部署兼容已有数据库结构的 Worker，再向前修复。
