---
title: iOS App 与快捷指令
description: 通过快捷指令直接上报，或交给 PutSMS App 可靠采集和同步短信。
---

iOS 不允许第三方 App 直接读取系统短信。因此，无论选择哪种方式，都需要先在系统的**快捷指令** App 中创建“收到信息”个人自动化，由它取得发送方、正文和接收时间并触发采集。配置完成后，日常收到短信时会自动运行，无需手动打开快捷指令。

## 选择采集方式

| 能力 | 快捷指令直接上报 | 快捷指令 + PutSMS App |
| --- | --- | --- |
| 采集触发 | 快捷指令自动化 | 快捷指令自动化 |
| 配置方式 | 使用 Dashboard Connect 生成的 Put URL | SMS registration，或手动填写 API 地址和 Device Key |
| 本地历史记录 | 不支持 | 支持 |
| 断网或失败后重试 | 不支持 | 本地保留，后续重新上传 |
| 后台上传 | 不支持 | 支持，由 iOS 调度 |
| 端到端加密 | 不支持，仅有 HTTPS 传输加密 | 支持 PutSMS E2EE |
| 日常是否需要打开 App | 不需要 | 不需要 |
| 适用场景 | 简单、低频、可接受偶发丢失 | 长期使用或敏感短信，推荐 |

两种方式不要同时用于同一条自动化，否则可能产生重复记录。需要可靠保存、失败补传或端到端加密时，应选择 PutSMS App。

## 方案一：快捷指令直接上报

这种方式不调用 PutSMS App，而是让快捷指令直接向 PutSMS API 发起请求。它配置简单，但每次执行都是一次独立上报，没有本地队列或失败恢复能力。

<Steps>

### 获取 Put URL

在 Dashboard 创建 iOS 设备，在 Connect 中选择 **Put URL**，生成凭据并复制仅显示一次的地址：

```text
https://<api-domain>/put/<deviceKey>
```

### 创建短信自动化

在快捷指令中创建“收到信息”个人自动化，并添加**获取 URL 内容**动作。使用 `POST` 请求 Put URL，将短信变量映射为以下 JSON 字段：

```json
{
  "sender": "[发送方]",
  "content": "[信息正文]",
  "receivedAt": "[接收时间]"
}
```

`sender` 和 `content` 必填；`receivedAt` 可选。关闭执行前询问，使自动化可以在短信到达时直接运行。

### 验证上报

发送一条测试短信，然后在 [Dashboard 的 Messages](/zh/docs/guides/dashboard) 中核对发送方、正文、时间和来源设备。

</Steps>

<Callout type="warn" title="没有失败或无网重试">
  直接上报是否成功取决于本次自动化执行时的网络和 API 响应。快捷指令不会保存待上传短信；请求失败后，恢复网络也不会自动补传。
</Callout>

<Callout type="warn" title="保护 Device Key">
  Put URL 中包含 Device Key，请像密码一样保护它。不要分享该快捷指令，也不要发送包含完整 URL 的截图。轮换 Device Key 或更换 API 地址后，必须修改所有相关快捷指令中的 URL。
</Callout>

快捷指令直接发送的是明文 JSON。HTTPS 可以保护传输过程，但这种方式不会生成 PutSMS 端到端密文，服务端仍能接触短信内容。

## 方案二：通过 PutSMS App 采集

此方式仍由快捷指令自动化取得短信，但最后调用 PutSMS 的 `Record Message` App Intent。App 会先把短信写入本地数据库，再立即尝试上传；如果当时断网或请求失败，记录会保留为待上传状态，之后由同步流程重试。

<Steps>

### 连接 App

在 Dashboard 创建 iOS 设备。App 版本支持自动兑换时可选择 **SMS registration**；也可以选择 **API Key**，手动填写 API 地址和仅显示一次的 Key。完成初始绑定和所需权限配置后，日常采集不要求 App 保持前台运行。

### 添加 App Intent

在“收到信息”自动化中添加 PutSMS 的 `Record Message` 动作，将发送方、正文和接收时间映射到对应参数；有接收号码时也可以填写 Receiver。关闭执行前询问。

### 验证本地采集

发送一条测试短信，确认它先出现在 PutSMS 的本地历史记录中，再到 [Dashboard 的 Messages](/zh/docs/guides/dashboard) 确认云端记录。

### 验证失败补传

断开网络后再接收一条测试短信，确认本地仍保留记录。恢复网络后等待后台同步，或打开 App 手动同步，并确认待上传记录最终出现在 Dashboard。

</Steps>

App Intent 执行时无需手动打开 PutSMS，App 也不需要一直在前台运行。不过，后台上传由 iOS 根据电量、网络和使用情况调度，不能保证在固定时间点执行或始终实时完成。

## 端到端加密

PutSMS App 可以在短信离开设备前生成端到端密文。启用**要求加密上传**之前，请按照[端到端加密](/zh/docs/guides/encryption)配置阅读端密钥并安全备份私钥。

启用后，如果没有可用的接收方公钥，App 会保留待上传记录并停止上传，不会自动降级为明文。快捷指令直接上报不具备此能力。
