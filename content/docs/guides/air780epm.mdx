---
title: Air780EPM
description: Configure reliable SMS forwarding on LuatOS hardware.
---

<Steps>

### Prepare the device

Use an Air780EPM with LuatOS V2018 or newer, an internet-capable SIM, and Luatools. Create a device in Dashboard and use `embedded` as its descriptive platform.

### Generate an enrollment code

In the Connect dialog choose **SMS registration**, then **Generate code**. This is the recommended provisioning path for compatible firmware. The `XXXX-XXXX` code expires after ten minutes and can be used only once.

### Send the registration SMS

Send the following message to the SIM installed in the Air780EPM:

```text
PUTSMS REG XXXX-XXXX
```

For a self-hosted API, append its HTTPS origin:

```text
PUTSMS REG XXXX-XXXX https://sms.example.com
```

The device redeems the code, stores its generated credential atomically in `/putsms_device.json`, confirms configuration, and sends a result SMS. Redemption immediately marks the Dashboard device connected. Existing manually provisioned devices may retain `put_url`; direct provisioning can also use Put URL or API Key when the firmware integration supports it, while new SMS-enrolled devices should leave `put_url` empty.

```lua
return {
  put_url = "",
  allow_insecure_http = false,
  sms_encoding_debug = false,
  crypto_capability_probe = true,
  default_api_base_url = "https://api.putsms.com",
  client_version = VERSION or "001.999.006",
  request_timeout_ms = 15000,
  queue_max_items = 500,
  queue_max_bytes = 512 * 1024,
}
```

### Flash and verify

Flash the Lua files and firmware, wait for cellular and SNTP readiness, then complete enrollment and send a test SMS. Confirm the connection in Dashboard, verify the message in PutSMS, and check that `/putsms_queue.json` eventually empties.

</Steps>

Failed uploads remain in a persistent queue and retry after restart or network recovery. The registration command is also queued and uploaded in full after enrollment. Messages and registration commands are plaintext on the hardware and upload as plaintext JSON through HTTPS; restrict physical access. To provision the modem again, choose **Disconnect**, select the desired method, and generate a new credential. See the [project reference](/docs/air780epm) for logs and failure codes.
