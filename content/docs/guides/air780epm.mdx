---
title: Air780EPM
description: Configure reliable SMS forwarding on LuatOS hardware.
---

<Steps>

### Prepare the device

Use an Air780EPM with LuatOS V2018 or newer, an internet-capable SIM, and Luatools. Create an `embedded` device in Dashboard.

### Generate an enrollment code

Open the embedded device's connection settings and choose **Generate SMS code**. The `XXXX-XXXX` code expires after ten minutes and can be used only once.

### Send the registration SMS

Send the following message to the SIM installed in the Air780EPM:

```text
PUTSMS REG XXXX-XXXX
```

For a self-hosted API, append its HTTPS origin:

```text
PUTSMS REG XXXX-XXXX https://sms.example.com
```

The device redeems the code, stores its generated credential atomically in `/putsms_device.json`, confirms configuration, and sends a result SMS. Uploads start only after confirmation. Existing manually provisioned devices may retain `put_url`; new devices should leave it empty.

```lua
return {
  put_url = "",
  allow_insecure_http = false,
  sms_encoding_debug = false,
  crypto_capability_probe = true,
  default_api_base_url = "https://api.putsms.com",
  client_version = VERSION or "001.999.006",
  request_timeout_ms = 15000,
  queue_max_items = 500,
  queue_max_bytes = 512 * 1024,
}
```

### Flash and verify

Flash the Lua files and firmware, wait for cellular and SNTP readiness, then complete enrollment and send a test SMS. Confirm the connection in Dashboard, verify the message in PutSMS, and check that `/putsms_queue.json` eventually empties.

</Steps>

Failed uploads remain in a persistent queue and retry after restart or network recovery. The registration command is also queued and uploaded in full after enrollment. Messages and registration commands are plaintext on the hardware and upload as plaintext JSON through HTTPS; restrict physical access. To move the modem to another account, choose **Unbind device**, generate a new code, and send a new registration SMS. See the [project reference](/docs/air780epm) for logs and failure codes.
