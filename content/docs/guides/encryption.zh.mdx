---
title: 端到端加密
description: 生成、备份、恢复和轮换 PutSMS 客户端密钥。
---

PutSMS E2EE 使用 AES-256-GCM 加密每条短信，再使用 RSA-OAEP-SHA256 为获授权阅读端封装消息密钥。Dashboard、iOS 和浏览器扩展使用本地私钥解密。

<Steps>

### 生成阅读端密钥

在可信的 Dashboard 或 iOS 客户端生成密钥，只向 API 注册公钥。

### 备份私钥

导出恢复/私钥 JSON，保存到加密密码管理器或离线保险库。服务端无法重建丢失的私钥。

### 导入其他阅读端

将备份导入每个需要阅读加密短信的可信 Dashboard 配置、iOS 设备或浏览器扩展。在 iOS 中，应先选择可见的来源设备，再选取对应备份。PutSMS 会校验备份是否属于该设备，在共享 Keychain 中保存多把私钥，并提供给通知服务扩展使用。服务端绑定失败时会标记为等待绑定，之后自动重试。

### 要求加密上传

确认所有预期阅读端均有可用密钥后，在 iOS 开启**要求加密上传**。此后如果没有可用公钥，上传会关闭失败。

### 谨慎轮换

先添加新密钥并验证解密，再停用旧密钥。阅读历史密文可能仍需保留旧私钥备份。

</Steps>

<Callout type="warn" title="明确非 E2EE 来源">Android SmsForwarder 和 Air780EPM 当前通过 HTTPS 发送明文 JSON。Air780EPM 可以探测固件的 TRNG/AES-GCM 能力，但不支持 RSA-OAEP 或 PutSMS E2EE；其纯 Lua RSA 实验已回滚。服务端加密可保护静态数据，但不能向 Worker 隐藏内容。</Callout>
