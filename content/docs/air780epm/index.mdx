---
title: PutSMS for Air780EPM
description: Reliably receive SMS on Air780EPM and forward them to PutSMS.
---

This LuatOS app reliably forwards SMS received by an Air780EPM to PutSMS. Failed uploads remain on the device filesystem and resume after restart or network recovery. SMS registration is the recommended setup; compatible integrations may also use a manual Put URL or API Key.

<Callout type="warn" title="Current security boundary">Message uploads and enrollment credentials are application-layer plaintext protected by HTTPS. Pending messages and registration commands are plaintext in `/putsms_queue.json`. Air780EPM does not currently support RSA-OAEP or PutSMS E2EE; the pure-Lua RSA-2048 experiment was reverted because it blocked real hardware long enough to trigger module protection.</Callout>

## Files

- `main.lua`: application entry point.
- `sms_app.lua`: SMS receiving and scheduled carrier query.
- `sms_text.lua`: UTF-8, CESU-8, and UTF-16BE/UCS-2 normalization.
- `crypto_probe.lua`: safe startup probe for firmware TRNG and AES-GCM capabilities.
- `putsms_device.lua`: atomic persistence and power-loss recovery for enrollment configuration.
- `putsms_registration.lua`: registration parsing, credential redemption, confirmation, and reply SMS.
- `sms_sender.lua`: serialized registration replies and carrier query messages.
- `sntp_app.lua`: network time synchronization.
- `putsms_config.lua`: default API origin and legacy manual Put URL compatibility.
- `putsms_queue.lua`: persistent upload queue.
- `putsms_client.lua`: upload, response validation, and retry logic.

## Requirements

- Air780EPM and an internet-capable SIM.
- Air780EPM LuatOS firmware V2018 or newer.
- Luatools.
- A PutSMS account.

## SMS enrollment

1. Create a device in Dashboard and choose `embedded` as its descriptive platform.
2. In Connect choose **SMS registration** and generate a one-time code.
3. Send `PUTSMS REG XXXX-XXXX` to the modem SIM.
4. For a self-hosted API, send `PUTSMS REG XXXX-XXXX https://sms.example.com`.

Codes expire after ten minutes and are single-use. The modem redeems the code for a generated Device Key, persists configuration in `/putsms_device.json`, confirms it with the API, and sends a result SMS. Redemption marks the Dashboard device connected. The same device record may instead use Put URL or API Key for manual provisioning when the firmware integration supports it.

Existing manually provisioned devices can retain a Put URL. New devices should leave it empty:

```lua
return {
    put_url = "",
    allow_insecure_http = false,
    sms_encoding_debug = false,
    crypto_capability_probe = true,
    default_api_base_url = "https://api.putsms.com",
    client_version = VERSION or "001.999.006",
    request_timeout_ms = 15000,
    queue_max_items = 500,
    queue_max_bytes = 512 * 1024,
}
```

Production must use HTTPS. Enable `allow_insecure_http` only while testing a local Worker on a trusted network. `crypto_capability_probe` performs a metadata-only in-memory check for TRNG and AES-GCM; it does not encrypt uploads and must not be treated as E2EE support.

## Flash and verify

Flash all Lua files and the target firmware with Luatools. Wait for cellular and SNTP readiness, complete SMS enrollment, then send a test SMS. Confirm the connection and message in PutSMS, and verify `/putsms_queue.json` eventually empties.

Successful logs omit the message body and Put URL:

```text
I/sms.received sender 10001 bytes 48
I/putsms.queue.enqueued id 7f31a9c2 items 1
I/putsms.upload.request id 7f31a9c2 sender 10001 received_at 2026-09-16T19:00:00Z body_bytes 241
I/putsms.upload.response id 7f31a9c2 status 200 accepted true body {"ok":true,"messageId":"air780epm-..."}
I/putsms.upload.success id 7f31a9c2 status 200 message_id air780epm-... remaining 0
```

## Troubleshooting

- `putsms.config.invalid`: empty or invalid Put URL, or an unsafe protocol.
- `putsms.upload.auth_failed`: Device Key is invalid, revoked, or rotated.
- `putsms.upload.retry`: network, timeout, rate limit, or temporary server failure; retries use backoff.
- `putsms.upload.rejected`: invalid fields or conflicting duplicate ID; the task is paused.
- `putsms.queue.full`: queue reached 500 items or 512 KiB.
- `putsms.queue.corrupt`: neither primary nor backup queue can be parsed; preserve files for investigation.

Use **Disconnect** in Dashboard before provisioning the modem again. Disconnect immediately invalidates its current token and unused registration code while preserving the device record and messages; choose a method and generate a new credential to reconnect it.

## Persistence and privacy

The queue uses temporary files, backups, and rename operations. It removes a task only after the service confirms `ok=true` with a `messageId`. Registration commands are queued like other messages and uploaded in full after enrollment. Logs omit complete message bodies and Put URLs. Never commit real configuration, queue files, or device logs.

Incoming text is normalized to UTF-8 before enqueueing. Valid UTF-8 is preserved; CESU-8 surrogate pairs and explicit UTF-16BE/UCS-2 are converted, while unrecoverable bytes become Unicode replacement characters.

## Carrier query SMS

The sample behavior sends `102` to China Telecom `10001` every ten minutes after startup. Carrier replies are uploaded as regular received messages; remove or change this behavior when it is not appropriate for your SIM.
