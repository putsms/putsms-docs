title: PutSMS for Air780EPM
description: 在 Air780EPM 上可靠地接收短信并上传至 PutSMS。
---

该 LuatOS 应用收到短信后将其可靠上传至 PutSMS。失败任务保存在设备文件系统，重启或网络恢复后继续补传。推荐使用短信注册；兼容的集成也可以使用手工 Put URL 或 API Key。

<Callout type="warn" title="当前安全边界">短信上传和注册凭据是由 HTTPS 保护的应用层明文；待上传短信与注册命令也以明文保存在 `/putsms_queue.json`。Air780EPM 当前不支持 RSA-OAEP 或 PutSMS E2EE；纯 Lua RSA-2048 实验因真机长时间阻塞并触发模组保护而回滚。</Callout>

## 短信注册

1. 在 Dashboard 创建设备，并选择 `embedded` 作为描述性平台。
2. 在 Connect 中选择 **SMS registration**，生成一次性注册码。
3. 向模组 SIM 卡发送 `PUTSMS REG XXXX-XXXX`。
4. 自部署 API 使用 `PUTSMS REG XXXX-XXXX https://sms.example.com`。

注册码十分钟后过期且只能使用一次。模组兑换注册码取得 Device Key，将配置原子保存到 `/putsms_device.json`，向 API 确认后发送结果短信；兑换后 Dashboard 会显示 Connected。固件集成支持时，同一设备记录也可以使用 Put URL 或 API Key 手工配置。

已有手工配置设备可继续使用 Put URL；新设备应将其留空：

```lua
return {
  put_url = "",
  allow_insecure_http = false,
  sms_encoding_debug = false,
  crypto_capability_probe = true,
  default_api_base_url = "https://api.putsms.com",
  client_version = VERSION or "001.999.006",
  request_timeout_ms = 15000,
  queue_max_items = 500,
  queue_max_bytes = 512 * 1024,
}
```

`crypto_capability_probe` 只在内存中探测固件的 TRNG 与 AES-GCM 能力，不会加密上传，也不代表支持 E2EE。

## 故障处理

- `putsms.config.invalid`：Put URL 为空、格式或协议错误。
- `putsms.upload.auth_failed`：Device Key 已失效、撤销或轮换。
- `putsms.upload.retry`：网络、超时、限流或服务端临时错误，将自动退避重试。
- `putsms.upload.rejected`：字段错误或重复 ID 内容冲突，任务会暂停。
- `putsms.queue.full`：队列达到 500 条或 512 KiB。
- `putsms.queue.corrupt`：主队列和备份均无法解析，应保留文件排查。

重新配置模组前，在 Dashboard 使用 **Disconnect**。这会立即使现有 Token 和未使用注册码失效，同时保留设备记录和短信；随后重新选择连接方式并生成凭据。

注册命令会和普通短信一样进入持久化队列，并在注册完成后以完整原文上传。日志不会输出完整短信正文或 Put URL。不要将真实配置、队列文件或设备日志提交到版本库。

收到的文本会在入队前规范为 UTF-8：合法 UTF-8 原样保留，CESU-8 代理对和明确的 UTF-16BE/UCS-2 会被转换，不可恢复字节使用 Unicode 替换字符。
