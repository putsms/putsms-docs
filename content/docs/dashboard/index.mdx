Dashboard frontend for PutSMS. This project is deployed as Cloudflare Pages and talks to the backend Worker in `../putsms-api`.

## Local Development

1. Start the backend:

```sh
cd ../putsms-api
npm run dev
```

2. Start the frontend:

```sh
cd ../putsms-dash
npm run dev
```

Open `http://localhost:5173`.

## Environment

- `VITE_API_BASE_URL`: backend Worker origin. Local example: `http://localhost:8787`. LAN or Tailscale example: `http://100.99.240.60:8787`. Production example: your deployed Worker URL.

Development requires `VITE_API_BASE_URL` in `.env` because the frontend calls the Worker directly. The Vite dev server does not proxy `/api` requests.

Example `.env`:

```bash
VITE_API_BASE_URL=http://localhost:8787
```

If you open the frontend from another device, use an API origin that device can reach:

```bash
VITE_API_BASE_URL=http://100.99.240.60:8787
```

## Commands

- `npm run dev`: run the React Router SPA dev server on port `5173`.
- `npm run typecheck`: generate React Router types and run TypeScript.
- `npm test`: run frontend unit tests.
- `npm run build`: build the static frontend into `build/client`.
- `npm run preview`: preview the built frontend locally.
- `npm run deploy`: deploy `build/client` to Cloudflare Pages.

## Notes

The frontend does not own API routes. API calls, SSE connections, Google OAuth start URLs, and generated connection endpoints all use `VITE_API_BASE_URL`.

## Device Connections

Creating a device stores its name and descriptive platform, then opens the Connect dialog. The Status column is the only connection-management entry point. Every platform can use API Key, Put URL, or SMS registration.

API Key and Put URL generate the same long-lived Device Key; Dashboard shows either a Bearer header or key-bearing URL according to the selected method. Generating a Key produces `Ready`, and the first successful authenticated request produces `Connected`. SMS registration creates a single-use ten-minute code and becomes connected when redeemed. **Disconnect** revokes both credential forms and resets connection state without deleting the device or its data.
